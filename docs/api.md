# AL API guide for client developers (US-311)

The full, always-current reference is generated by FastAPI at **http://localhost:8000/docs**
(try every endpoint there). This page explains how to connect.

## 1. Connecting to the local stack

| Thing | From a browser / laptop | From the Android emulator |
|---|---|---|
| API | `http://localhost:8000` | `http://192.168.0.50:8000` |
| Auth emulator | `localhost:9099` | `192.168.0.50:9099` |
| Firestore emulator | `localhost:8080` | `192.168.0.50:8080` |

Project ID for local work: `demo-al-group11`. A `demo-` project only ever talks to the emulators,
so nothing can reach a real database by mistake.

**Kotlin (Android)** — call once at app start, before any other Firebase call, in debug builds only:

```kotlin
Firebase.auth.useEmulator("192.168.0.50", 9099)
Firebase.firestore.useEmulator("192.168.0.50", 8080)
```

Plain `http://` to 192.168.0.50 needs a debug network-security config that allows cleartext to that host.

**React (web)**:

```js
connectAuthEmulator(auth, "http://localhost:9099");
connectFirestoreEmulator(db, "localhost", 8080);
```

## 1a. Mobile quick start (US-112, US-121)

Everything below runs on your laptop. The Android emulator reaches the laptop as `10.0.2.2`,
so the app uses `http://10.0.2.2:8000` (API), `10.0.2.2:9099` (Auth) and `10.0.2.2:8080`
(Firestore). The `curl` commands use `localhost` because they run on the laptop itself.

1. **Start the stack and seed it** (repo root):

   ```bash
   docker compose up --build
   # in a second terminal:
   export FIRESTORE_EMULATOR_HOST=localhost:8080 FIREBASE_AUTH_EMULATOR_HOST=localhost:9099
   python scripts/seed_emulator.py
   ```

   Without Docker, use README "Option B" instead; the ports are the same.

2. **Sign in as the demo borrower** and copy `idToken` from the response.
   Demo login: `aoife@example.com` / `al-demo-pass` (emulator only, not a real account).
   The emulator accepts any `key` value.

   ```bash
   curl -s -X POST "http://localhost:9099/identitytoolkit.googleapis.com/v1/accounts:signInWithPassword?key=any" \
     -H 'Content-Type: application/json' \
     -d '{"email":"aoife@example.com","password":"al-demo-pass","returnSecureToken":true}'
   export TOKEN=<idToken from the response>
   ```

   In the app you do not need this step: sign in with `Firebase.auth` (pointed at the emulator)
   and use `getIdToken()` as in section 2.

3. **Get a valuation, then submit the application** (body from section 3):

   ```bash
   curl -s -X POST localhost:8000/valuations -H "Authorization: Bearer $TOKEN" \
     -H 'Content-Type: application/json' \
     -d '{"county":"Cork","floorAreaM2":110,"bedrooms":3,"propertyType":"semi_detached","ber":"B2"}'
   # -> 201 {"valuationId":"...","estimate":349000.0,"low":286000.0,"high":425000.0,"modelVersion":"gbr-1","isStub":false}

   curl -s -X POST localhost:8000/applications -H "Authorization: Bearer $TOKEN" \
     -H 'Content-Type: application/json' \
     -d '{"buyerType":"first_time",
          "financials":{"grossAnnualIncome":95000,"monthlyDebts":300,"deposit":60000,"loanAmount":335000,"termYears":30},
          "property":{"county":"Cork","floorAreaM2":110,"bedrooms":3,"propertyType":"semi_detached","ber":"B2","askingPrice":395000},
          "valuationId":"<valuationId from the call above>"}'
   # -> 201 {"id":"AL-2026-0122",...,"status":"applied","statusLabel":"Applied",...,"metrics":{"lti":3.5263,"ltv":0.9599,...}}
   ```

4. **Check it landed in Firestore**: open http://localhost:4000/firestore → `applications` →
   the new ID, or from the command line (`Bearer owner` = emulator admin, skips the rules):

   ```bash
   curl -s -H "Authorization: Bearer owner" \
     "http://localhost:8080/v1/projects/demo-al-group11/databases/(default)/documents/applications/AL-2026-0122"
   ```

   `fields.status.stringValue` must be `"applied"`.

**Registration (US-101)** writes `users/{uid}` directly, so it must match the security rules
exactly: `uid`, `email` (the email from the sign-in token), `displayName`, `role: "borrower"` and
`createdAt: FieldValue.serverTimestamp()`. Nothing else is allowed. See `docs/data-model.md` 2.1.

## 2. Calling the API

Every request needs the signed-in user's Firebase ID token:

```
Authorization: Bearer <ID token>
```

Kotlin: `Firebase.auth.currentUser!!.getIdToken(false).await().token`
JS: `await auth.currentUser.getIdToken()`

The API reads the user's role from the token. Borrowers have no role claim; brokers and
underwriters get `role` set by the seed script.

## 3. Endpoints (Sprint 1)

| Method & path | Who | What | Story |
|---|---|---|---|
| `GET /health` | anyone | Is the API up | — |
| `POST /valuations` | signed in | Property spec → `estimate`, `low`, `high` (80% range), `modelVersion` + `valuationId`. **`isStub: true` = the model file is missing and the numbers are fake**; clients decide on this flag, not on the amount | US-121, US-403 |
| `POST /applications` | borrower | Submit an application → status `applied` | US-112 |
| `GET /applications/{id}` | owner, assigned broker, underwriter | Read one application (404 if not yours) | US-311 |
| `POST /applications/{id}/status` | per state machine | `{ "to": "<status>", "reason": "..." }` | US-302 |

Live lists (pipeline, "my applications", status timeline) are **not** API calls: read Firestore
directly with a listener. Required queries are in `docs/data-model.md` section 4.

### Example: submit an application

```json
POST /applications
{
  "buyerType": "first_time",
  "financials": { "grossAnnualIncome": 95000, "monthlyDebts": 300, "deposit": 60000,
                  "loanAmount": 335000, "termYears": 30 },
  "property": { "county": "Cork", "floorAreaM2": 110, "bedrooms": 3,
                "propertyType": "semi_detached", "ber": "B2", "askingPrice": 395000 },
  "valuationId": "<from POST /valuations, optional>"
}
```

Response `201`: the stored application (`id` like `AL-2026-0122`, `status: "applied"`,
`statusLabel: "Applied"`, `metrics` filled by the calculation module: `lti`, `ltv`, `dti`,
`stressedDti`, `monthlyRepayment` and `checks` with `ltiOk`, `ltvOk`, `dtiOk`, `stressedDtiOk`.
`lti` and the DTI values are `null` when income is 0).

## 4. Errors — always the same shape

```json
{ "error": { "code": "validation_error", "message": "Some fields are missing or invalid.",
             "details": [ { "field": "financials.termYears", "message": "Input should be less than or equal to 35" } ] } }
```

| HTTP | `code` | Meaning |
|---|---|---|
| 401 | `unauthenticated` | Missing, invalid or expired token |
| 403 | `forbidden` / `actor_not_allowed` | Your role may not do this |
| 404 | `not_found` | Does not exist, or you may not see it |
| 409 | `invalid_transition` | Status change not allowed from the current status |
| 422 | `validation_error` / `reason_required` | Bad input; `details` lists the fields |
| 400 | `bad_valuation` | `valuationId` unknown or not yours |

Show `message` to the user; use `details[].field` to highlight form fields.
