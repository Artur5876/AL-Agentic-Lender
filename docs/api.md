# AL API guide for client developers (US-311)

The full, always-current reference is generated by FastAPI at **http://localhost:8000/docs**
(try every endpoint there). This page explains how to connect.

## 1. Connecting to the local stack

| Thing | From a browser / laptop | From the Android emulator |
|---|---|---|
| API | `http://localhost:8000` | `http://192.168.0.50:8000` |
| Auth emulator | `localhost:9099` | `192.168.0.50:9099` |
| Firestore emulator | `localhost:8080` | `192.168.0.50:8080` |

Project ID for local work: `demo-al-group11`. A `demo-` project only ever talks to the emulators,
so nothing can reach a real database by mistake.

**Kotlin (Android)** — call once at app start, before any other Firebase call, in debug builds only:

```kotlin
Firebase.auth.useEmulator("192.168.0.50", 9099)
Firebase.firestore.useEmulator("192.168.0.50", 8080)
```

Plain `http://` to 192.168.0.50 needs a debug network-security config that allows cleartext to that host.

**React (web)**:

```js
connectAuthEmulator(auth, "http://localhost:9099");
connectFirestoreEmulator(db, "localhost", 8080);
```

## 2. Calling the API

Every request needs the signed-in user's Firebase ID token:

```
Authorization: Bearer <ID token>
```

Kotlin: `Firebase.auth.currentUser!!.getIdToken(false).await().token`
JS: `await auth.currentUser.getIdToken()`

The API reads the user's role from the token. Borrowers have no role claim; brokers and
underwriters get `role` set by the seed script.

## 3. Endpoints (Sprint 1)

| Method & path | Who | What | Story |
|---|---|---|---|
| `GET /health` | anyone | Is the API up | — |
| `POST /valuations` | signed in | Property spec → estimate + `valuationId`. **`isStub: true` = fake fixed numbers until the AI model is connected** | US-121, US-403 |
| `POST /applications` | borrower | Submit an application → status `applied` | US-112 |
| `GET /applications/{id}` | owner, assigned broker, underwriter | Read one application (404 if not yours) | US-311 |
| `POST /applications/{id}/status` | per state machine | `{ "to": "<status>", "reason": "..." }` | US-302 |

Live lists (pipeline, "my applications", status timeline) are **not** API calls: read Firestore
directly with a listener. Required queries are in `docs/data-model.md` section 4.

### Example: submit an application

```json
POST /applications
{
  "buyerType": "first_time",
  "financials": { "grossAnnualIncome": 95000, "monthlyDebts": 300, "deposit": 60000,
                  "loanAmount": 335000, "termYears": 30 },
  "property": { "county": "Cork", "floorAreaM2": 110, "bedrooms": 3,
                "propertyType": "semi_detached", "ber": "B2", "askingPrice": 395000 },
  "valuationId": "<from POST /valuations, optional>"
}
```

Response `201`: the stored application (`id` like `AL-2026-0122`, `status: "applied"`,
`statusLabel: "Applied"`, `metrics: null` until the calculation module is connected).

## 4. Errors — always the same shape

```json
{ "error": { "code": "validation_error", "message": "Some fields are missing or invalid.",
             "details": [ { "field": "financials.termYears", "message": "Input should be less than or equal to 35" } ] } }
```

| HTTP | `code` | Meaning |
|---|---|---|
| 401 | `unauthenticated` | Missing, invalid or expired token |
| 403 | `forbidden` / `actor_not_allowed` | Your role may not do this |
| 404 | `not_found` | Does not exist, or you may not see it |
| 409 | `invalid_transition` | Status change not allowed from the current status |
| 422 | `validation_error` / `reason_required` | Bad input; `details` lists the fields |
| 400 | `bad_valuation` | `valuationId` unknown or not yours |

Show `message` to the user; use `details[].field` to highlight form fields.
